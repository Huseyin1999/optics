#Инструкция для работы с программой моделирования триггера телескопов TAIGA-IACT
Программа расположена в каталоге ``/k38/taiga_pool/iact_trigger/trg4/``. Перейдите в этот каталог для работы с программой.
##Компиляция
не требуется, но для работы с программой моделирования триггера на сервере gridmsu31 необходимо установить библиотеки: numpy pandas tqdm scipy. Сделать это можно командой:

```pip install numpy pandas tqdm scipy```

Затем в папке configs создайте свою копию файла ``trigger_configs.json`` в этой же папке. Вся настройка моделирования происходит внутри данного файла.

##Настраиваемые параметры
###Вспомогательные файлы
Все файлы координат пикселей, коэффицентов относительной чувтствительности ФЭУ и разверток импульсов медленного формирователя камер, которые я когда-либо использовал в моделировании, расположены в папке ``Calibration``.
###IACTs
IACTs - список телескопов для моделирования. Нуменация от 1 до 5. Номер телескопа связан только с его координатами:
|  IACT  | x,m       | y,m       |
|--------|-----------|-----------|
|    1   | 108.5218  | 91.30141  |
|    2   | -35.51704 | -197.1544 |
|    3   | 329.6131  | -361.2197 |
|    4   | 210.0     | -139.0    |
|    5   | 419.86    | 23.46     |

Пример заполнения: IACTs = [1,2,3,4,5] - моделирование всех 5 телескопов ( если исходный файл их содержит)

###pulse_files
pulse_files - путь к файлам, содержащим форму импульса медленного формирователя. Все файлы, которые могут понадобиться для моделирования (формы импульсов, координат пикселей и их относительных чувствительностей)лежат в папке ``Calibration``. При моделировании камеры в режиме полного считывания (когда в каждом событии записываются амплитуды всех пикселей) используется файл ``Calibration/slow_pulse_iact2_new``. 
Для моделирования камеры со считыванием "с подхватом", когда событие включает только те кластеры, в которых выработался триггер используйте файл импульса ``slow_pulse_cam1_old.txt``. Пример заполнения:
         
```
pulse_files = [
    '/k38/taiga_pool/iact_trigger/launch/Calibration/slow_pulse_cam1_old.txt',
    '/k38/taiga_pool/iact_trigger/launch/Calibration/slow_pulse_iact2_new',
    '/k38/taiga_pool/iact_trigger/launch/Calibration/slow_pulse_iact2_new',
    '/k38/taiga_pool/iact_trigger/launch/Calibration/slow_pulse_iact2_new',
    '/k38/taiga_pool/iact_trigger/launch/Calibration/slow_pulse_iact2_new',
]
```
первый телескоп (первый по порядку заполнения в IACTs. То есть если заполнить IACTs = [2,3], для них будут все равно использоваться первые две строчки pulse_files) моделируется с имульсом для режима " с подхватом", остальные - со считыванием всей камеры.
###coord_files
coord_files - список путей к файлам координат телескопов
Пример:
```
coord_files = ['/k38/taiga_pool/iact_trigger/launch/Calibration/xy_turn_2019s_EP.txt',
              '/k38/taiga_pool/iact_trigger/launch/Calibration/XY_turn_2020jan2tel_18fix.txt',
              '/k38/taiga_pool/iact_trigger/launch/Calibration/XY_turn_2020jan2tel_18fix.txt',
              '/k38/taiga_pool/iact_trigger/launch/Calibration/XY_turn_2020jan2tel_18fix.txt',
              '/k38/taiga_pool/iact_trigger/launch/Calibration/XY_turn_2020jan2tel_18fix.txt',]
```
первый телескоп моделируется с координатной сеткой TAIGA-IACT01 (актуальной до лета 2022), остальные - с координатной сеткой TAIGA-IACT02 (актуальной до лета 2023)

###factors_path
factors_path - список путей к файлам относительной чувствительности пикселей. Даже если Вы в дальнейшем укажете что относительные чувствительности пикселей не используютсмя в Вашем варианте моделирования, здесь нужно какие-то файлы выбрать)
Пример:
```
factors_path = ['/k38/taiga_pool/iact_trigger/launch/Calibration/iact01_051019.factors',
               '/k38/taiga_pool/iact_trigger/launch/Calibration/factors_iact2_310120.led.txt',
               '/k38/taiga_pool/iact_trigger/launch/Calibration/factors_iact2_310120.led.txt',
               '/k38/taiga_pool/iact_trigger/launch/Calibration/factors_iact2_310120.led.txt',
               '/k38/taiga_pool/iact_trigger/launch/Calibration/factors_iact2_310120.led.txt',]
```
в данном примере, первый телескоп моделируется с чувствительностями ФЭУ TAIGA-IACT01 (актуальной до лета 2022), остальные - с чувствительностями ФЭУ TAIGA-IACT02 (актуальной до лета 2023)

###trigger_type
trigger_type - список типов триггеров для моделироуемых телескопов.     
    0 - с подхватом
    1 - полное считывание
Пример:
trigger_type = [0,1,1,1,1] - первый телескоп моделируется в режиме "с подхватом", остальные в режиме "полное считывание"
###integrate_window
integrate_window - время интегрирования сигнала. Этот параметр жестко связан с типом тирггера. Если trigger_type выбран 0, тогда время интегрирования 48ns. Если trigger_type выбран 1, тогда время интегрирования 80ns.
Пример:
integrate_window = [48,80,80,80,80] - настройка соответсвует trigger_type = [0,1,1,1,1]
###initial_file
initial_file - путь к исходному .feb файлу моделирования. Пример: 
```initial_file = '/k38/taiga_pool/CORSIKA_TAIGA/mc/all1102/bpe1102_31_da0.0_md5_a2021/taiga1102_feb'```
В случае, если удобнее прописывать путь к файлу моделирования из командной строки (если например Вы будете запускать моделирование с помощью внешнего скрипта перебирающего несколько файлов моделирования):
```initial_file = sys.argv[1]```
###gam
gam - Параметр играет роль только при записи направления прихода частицы в конечный файл моделирования. В случае выбора gam=1, будут записанны реальные направления прихода частиц. В случае gam=0 будут записанны случаные координаты в пределах круга, определяемых в [source_scatter_radius](#head1234), иммитируя наблюдение за источником.
###use_sense
use_sense - использование относительных чувствительностей ФЭУ. 1 - использовать, 0 - не использовать. Используйте только в случае работы с модифицированным оптическим моделированием. Понять какое моделировании оптики было выполнено можно по родителькой папке feb файла. В случае модифицированного запуска TAIGA_optics к версии оптической программы будет приписана буква "m". Например в случае ```bpe583_33m_da0.0_md5_wb1.22_old_cone/taiga583_feb'``` - 33 - версия оптической программы, m - при запуске TAIGA_optics использовались измененные спектральные чувствительности ФЭУ, позволяющие корректно моделировать чувствительность телескопов.
###sense_cam
Если use_sense это активация учета относительных чувствительностей пикселей камеры из файлов, указанных в factors_path, то sense_cam это общее общий для всей камеры поправочный коэффициент чувствительности к черенковскому свету. Определить подходящий коэффициент sense_cam можно на основе таблцы:
| Сезон   | Телескоп | sense_cam | mirror_q | sens | Конус    | PMT | Период       | Sigma |
| ------- | -------- | --------  | ------   | ---- | -------- | --- | ------------ | ----- |
| 2022-23 | IACT03   | 0.99      | 1.0      | 2.0  | new cone | UV  | без осени    | 5.5   |
| 2020-21 | IACT02   | 0.94      | 1.0      | 1.5  | old cone | —   | с 15 декабря | 3.8   |
| 2021-22 | IACT02   | 0.84      | 1.0      | 1.5  | old cone | —   | весь сезон   | 4.0   |
| 2022-23 | IACT02   | 0.73      | 1.0      | 1.5  | old cone | —   | весь сезон   | 4.5   |
| 2020-21 | IACT01   | 0.74      | 1.0      | 1.5  | old cone | —   | с 15 декабря | 3.0   |
| 2021-22 | IACT01   | 0.69      | 1.0      | 1.5  | old cone | —   | весь сезон   | 3.0   |
| 2022-23 | IACT01   | 0.85      | 1.0      | 1.5  | new cone | —   | весь сезон   | 5.0   |
mirror_q - параметр из файла parameters.txt внутри родительской папки моделирования оптики (например bpe583_33m_da0.0_md5_wb1.22_old_cone/parameters_old_cone.txt). 
sens - параметр указанный в том же файле в строке path_QE (например path_QE XP1911x1.5_pv.txt XP1911 - марка ФЭУ телескопа, 1.5 - коэффициент чувствительности, использованный в файле спектральной чувствительности ФЭУ).
Перед зпуском моделирования лучше убедиться что в файле parameters.txt параметры моделирования, соответствуют тому что указано в данной таблице. В противном случае не рекомендуется использоваь use_sense и sense_cam, то есть выставить их значения use_sense = 0 и sense_cam = [1.0,1.0,1.0,1.0 (и т.д. по числу телескопов в моделировании)]. На gridmsu все модифицированные моделирования оптики лежат в папке /k38/taiga_pool/CORSIKA_TAIGA/mc2. Все что лежит в папке /k38/taiga_pool/CORSIKA_TAIGA/mc нельзя использовать с активированными use_sense и sense_cam.
###save_path
save_path - путь по которому следует сохранить моделирование. Для этой цели создан каталог ``outs``
Пример:
save_path = '/k38/taiga_pool/iact_trigger/trg4/outs/TEST' - в outs будет создана папка TEST, содержащая Ваше моделирование. Сохранять можно и в Ваш домашний каталог и куда угодно еще.
###sim_name
В папке save_path будет создан каталог с названием, эквивалентным названию родительнской папки feb файла + _trg4 (версия программы триггера 4) в конце. Внутри этого каталога можно разместить любое количество моделирований триггера TAIGA-IACT на основе общего моделирования оптики. Каждое такое моделирование будет размещено в отдельном каталоге. Его имя определяется переменной sim_name. sim_name не должны повторяться. В противном случае моделирование триггера не запустится, программа скажет что конфигурация триггера с таким названием уже смоделирована.
###amplitudes_file
amplitudes_file - файл, содержащий распределение амплитуд XP1911 с учетом послеимпульсов. Его менять не надо. Но если нужно сделать все амплитуды фотоэлектронов одинаковыми, можно подменить этот файл.
###<a name="source_scatter_radius"></a> source_scatter_radius
source_scatter_radius - радиус круга в пределах которого будут выбираться случайные координаты направлений прихода при выборе параметра gam=0. Для gam=1 не имеет значения какой параметр будет здесь установлен, использоваться будут реальные направленя прихода ШАЛ.
###Параметры моделирования электроники триггера
t_grid, t_sign, trig_amp, t_hold, trig_window, t_after_before, max_n_channels_per_cluster - менять не нужно.
###hidden_mirror
hidden_mirror - для каждого телескопа можно исключить из моделирования зеркала.
###background
background - тип фона ночного неба
0 - Фон из заранее наигранного распределения амплитуд
1 - Использовать эксприментально измеренное распределние амплитуд
2 - Использовать распределение числа фотонов в единицу времени на пиксель
Здесь лучше выбирать опцию 0
###background_params
background_params - параметры моделирования фона
Пример:
```
background_params = {0:{'distribution background': {1: {'mean': 0.0, 'std': 2.5, 'n': 10000},
                                                    2: {'mean': 0.0, 'std': 2.5, 'n': 10000},
                                                    3: {'mean': 0.0, 'std': 2.5, 'n': 10000},
                                                    4: {'mean': 0.0, 'std': 2.5, 'n': 10000},
                                                    5: {'mean': 0.0, 'std': 2.5, 'n': 10000},
                                                        }},
                     1: {'experimental_background_path': {1: sys.argv[1:],
                                                          2: sys.argv[1:],
                                                          3: sys.argv[1:],
                                                          4: sys.argv[1:],
                                                          5: sys.argv[1:],
                                                         }},
                     2: {'mean_ph': 3, 'mean_phe_time': 35}}
```
Поскольку в предыдущем пункте был выбран background = 0, в данном примере имеет значение только часть:
```
background_params = {0:{'distribution background': {1: {'mean': 0.0, 'std': 2.5, 'n': 10000},
                                                    2: {'mean': 0.0, 'std': 2.5, 'n': 10000},
                                                    3: {'mean': 0.0, 'std': 2.5, 'n': 10000},
                                                    4: {'mean': 0.0, 'std': 2.5, 'n': 10000},
                                                    5: {'mean': 0.0, 'std': 2.5, 'n': 10000},
                                                        }},
```
Тем не менее, остальная часть структуры тоже нужна для корректной работы программы, хоть ни на что не влияет. 
1: {'mean': 0.0, 'std': 2.5, 'n': 10000} - 1 - первый телескоп, среднее значение фоновых амплитуд - 0.0, сигма: 2.5, n - количество амплитуд в распределении = 10000
Реалистичные сигмы фона представлены в таблице из раздела sense_cam в столбце Sigma.
####Во всех практических случаях в данной структуре я меняю только значения std!
###sigma_for_clean - опция для моделирования фона пикселей на основе экспериментальных пьедестальных данных. Менять не нужно.
###clean_edge
clean_edge1 - верхний порог клининга
clean_edge2 - нижний порог клининга 
###use_brightest_island
use_brightest_island  - следует ли выделять самый яркий остров в изображении. 0 - нет, 1 - да

make_trigger = 1 - следует ли провести моделирование триггера (1 - да, 0 - нет)
make_background = 1 - следует ли провести моделирование фона ночного неба (1 - да, 0 - нет)
make_cleaning = [1, "None"] - следует ли провести клининг и расчет параметров Хилласа (1 - да, 0 - нет)
В подавляющем большинстве случаев все три вышеописанных параметра имеют значения 1. Второй параметр в make_cleaning нужен только когда Вы не моделируете триггер и фон, но хотите сделать клининг. В качестве второй переменной кажите название каталога с фоном, к которому клининг будет применен.

####Остальные параметры в Вашей копии main_processing.py менять не рекомендуется

##Запуск обработки
После того как все параметры указанны, необходимо запустить моделирование из папки trg4.
```python3 main_processing.py configs/your_trigger_config.json path/to/taiga{number}_feb```

##Результаты работы программы
Если все прошло успешно, то в папке, которую Вы укажете в save_path будет сохранено моделирование. Папка будет содержать параметры исходного оптического моделирования, csv файлы конфигурации камер телескопов, копию файла your_trigger_config.json с параметрами Вашей обработки и распечатки событий без фона ночного неба и клининга. В папке b0 будут лежать файлы с наложенным фоном ночного неба. В папке b0/Ваш_клининг будут лежать scv таблицы с параметрами смоделированных событий и распечатки событий, прошедших клининг.
